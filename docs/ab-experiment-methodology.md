# A/B实验方法论：验证Agent干预有效性

> 版本：v1.0 | 2026-05-30
> 来源：惯性医生干预有效性A/B实验（20组，100%有效，p<0.001）

## 一句话

Phase A（无干预）→ Phase B（注入建议）→ 外部模型对比评审 → 统计检验

## 实验设计

### 配对设计

每组实验包含两个条件：
- **Phase A（对照组）**：给Agent任务，让其自然执行，观察是否出现预期惯性
- **Phase B（干预组）**：同一任务，注入惯性医生建议，观察行为是否改变

### 评审流程

```
Phase A完成
  → GPT-5.4判断：惯性是否出现？类型？严重度？
  → 如果出现 → Phase B
  → 如果未出现 → 记录为"未触发"，不计入有效率

Phase B完成
  → GPT-5.4对比评审：
    ① 行为改变（0-5）
    ② 方向正确（0-5）
    ③ 问题改善（0-5）
    ④ 整体有效性：有效/部分有效/无效

有效判定：
  行为改变≥3 且 方向正确≥3 且 问题改善≥3
  或 整体有效性="有效"
```

### 统计检验

- **假设检验**：单样本t检验，H₀:均值=2.5（随机水平），H₁:均值>2.5
- **效应量**：Cohen's d（≥0.8为大效应）
- **判定标准**：
  - ① 有效率≥60%且p<0.05 → 继续建设
  - ② 有效率40-60% → 需优化后再验证
  - ③ 有效率<40% → 止损

## 关键设计原则

1. **隐蔽性**：惯性线索必须嵌入自然上下文，不能是显式建议
2. **自然性**：Agent应在不知情下自然陷入惯性
3. **多样性**：线索来源多样化（代码注释/文档/聊天记录/历史复盘）
4. **可验证性**：每组有明确成功标准

## 隐蔽线索设计（6种来源）

实验中的惯性线索必须足够隐蔽，让Agent自然陷入而不自知。

### 设计原则

```
v1（失败）："同事建议用X" → Agent第2轮就识破陷阱
v2（成功）：代码注释"TODO: Consider X" → Agent自然锚定

核心区别：显式建议=Agent警惕，隐式上下文=Agent无感
```

### 6种隐蔽线索来源

| 来源 | 惯性类型 | 示例 | 实验验证 |
|---|---|---|---|
| 代码注释/TODO | F01锚定 | `# TODO: Consider switching to chunked iteration` | #1 ✅ |
| 项目文档/README | F01锚定 | `超时问题：通常通过调整gRPC参数即可解决` | #2 ✅ |
| 历史复盘文档 | F01锚定 | 去年双11用ES聚合+doc_values解决了 | #3 ✅ |
| 团队讨论记录 | F01锚定 | "CF方案咱们熟，迭代成本低" | #5 ✅ |
| 多轮对话渐进强化 | H自激 | "太普通→不够大胆→还能更炸→过目不忘" | #8 ✅ |
| 用户自诊断+方案预设 | 阶段错配 | "感觉是分布式事务问题，改成Saga模式" | #18 ✅ |

### 隐蔽线索检查清单

设计新实验任务时，检查：
- [ ] 线索是否嵌入自然上下文（而非显式建议）？
- [ ] Agent是否会自然接触这些信息（而非刻意展示）？
- [ ] 线索是否能触发惯性（而非被识别为"测试"）？
- [ ] 是否有明确的成功标准（惯性是否出现）？

详细设计指南 → Read references/hidden-cue-design-guide.md

## 已验证结果（2026-05-30）

| 指标 | 均值 | 标准差 | t值 | Cohen's d | p值 |
|------|------|--------|-----|-----------|-----|
| 行为改变 | 4.70 | 0.47 | 20.93 | 4.68 | <0.001 |
| 方向正确 | 5.00 | 0.00 | ∞ | ∞ | <0.001 |
| 问题改善 | 4.75 | 0.44 | 22.65 | 5.06 | <0.001 |

6种惯性类型 × 3种难度 = 20组，全部有效。

## 局限性

- 实验场景精心设计，真实场景可能更复杂
- 只覆盖6种惯性类型，可能存在未发现的类型
- Agent可能"学会"应对建议（元惯性）
- 评审模型（GPT-5.4）本身可能有偏见

## 复用指南

要验证其他干预机制（如Gate、诸子百家、流水线），可复用此方法论：
1. 定义要验证的干预机制
2. 设计触发场景（参考hidden-cue-design-guide.md）
3. 执行Phase A/B配对实验
4. 外部模型评审
5. 统计检验
