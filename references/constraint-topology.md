    32|      ↑
    33|  高  │  ❌ 开放拓扑         ⚠️ 穿孔拓扑

    35|      │
    36|  低  │  ✅ 封闭拓扑         ✅ 连通拓扑
    37|      │  代码/流水线          结构化输出
    38|      └──────────────────────────→ 确定性
    39|         低                      高

    44|## 0.1 观测者声明（v2.1新增，解R1）
    45|
    46|约束拓扑的判定依赖于**观测者位置**。同一约束在不同观测者视角下可能属于不同类型。
    47|
    48|```
    49|  观测者α(内部/Agent)     观测者β(外部/用户)
    50|      │                      │
    51|   ┌──▼──┐               ┌──▼──┐
    52|   │刚性 │◄──约束X──►    │弹性 │
    53|   │边界 │               │膜   │
    54|   └─────┘               └─────┘
    55|
    56|  实例："用中文回复"
    57|  Agent视角：刚性约束（S=1，无例外）
    58|  用户视角：弹性约束（用户可随时说"用英文"）
    59|
    60|  设计规则：
    61|  · 约束拓扑图必须标注观测者位置
    62|  · 动态切换时，观测者漂移可能导致约束类型误判
    63|  · 默认观测者=最终执行者（Agent）
    64|  · 用户否决权作为"元观测者"覆盖Agent判定
    65|```

    69|## 1. 概念本体
    70|
    71|### 1.1 定义
    72|
    73|**约束拓扑**是指令对LLM语义空间的**划分方式**——将模型的输出空间切割为"合法区域"和"非法区域"，拓扑的"形状"决定模型在推理时的路径数量和行为稳定性。
    74|
    75|```
    76|自然语言指令（开放拓扑）：
    77|
    78|   输入 ──→ [巨大的语义空间] ──→ ?
    79|                ↓   ↓   ↓   ↓   ↓
    80|                A   B   C   D   E  ... 无限可能出口
    81|
    82|   模型状态：犹豫、随机选择、依赖内部偏好
    83|
    84|约束拓扑指令（封闭拓扑）：
    85|
    86|   输入 ──→ [精确切割的语义空间] ──→ 唯一出口
    87|                ↑   ↑   ↑
    88|              约束1 约束2 约束3  (所有约束收敛于一点)
    89|
    90|   模型状态：确定性执行、无歧义、可预测
    91|```
    92|
    93|### 1.2 形式化定义
    94|
    95|```
    96|T(I) = (S_valid, S_invalid, ∂S)
    97|
    98|S_valid   = {o ∈ S(I) | o 满足所有约束}     —— 合法输出区域
    99|S_invalid = {o ∈ S(I) | o 违反至少一个约束} —— 非法输出区域
   100|∂S        = S_valid 与 S_invalid 的边界      —— 约束边界
   101|
   102|核心度量：
   103|  出口数 E(I) = |S_valid 的"路径聚类数"|
   104|  可执行熵 H = -Σ p(s) log p(s)  （连续谱，非二元）
   105|
   106|理想约束拓扑：E(I) = 1, H → 0
   107|```
   108|
   109|### 1.3 约束基元（基础单元）
   110|
   111|```
   112|┌─────────────────────────────────────────────────────┐
   113|│  约束基元 C = ⟨ Intention, Domain, Intensity ⟩      │
   114|│                                                     │
   115|│  意图(I)：限制种类                                   │
   116|│    ├─ 对象约束："针对什么实体"                       │
   117|│    ├─ 属性约束："应具有什么性质"                     │
   118|│    ├─ 关系约束："与何物如何关联"                     │
   119|│    ├─ 行为约束："能/不能执行什么操作"                │
   120|│    └─ 元约束："约束本身的可变性"                     │
   121|│                                                     │
   122|│  域(D)：作用范围                                     │
   123|│    ├─ 全局域：作用于整个任务执行轨迹                 │
   124|│    ├─ 局部域：作用于某一子步骤/对象                  │
   125|│    └─ 条件域：仅在条件触发时激活                     │
   126|│                                                     │
   127|│  强度(S)：[0,1] 连续值                               │
   128|│    0 = 完全柔性（偏好）                              │
   129|│    1 = 绝对刚性（硬性命令）                          │
   130|│    默认硬性约束 S=1，自然语言通常 S<0.7              │
   131|│                                                     │
   132|│  时间态(T)：（v2.1新增，解墨家攻击①）               │
   133|│    永久态：整个任务生命周期有效                      │
   134|│    阶段态：仅在特定阶段有效                          │
   135|│    临时态：有明确过期条件                            │
   136|│    动态切换时阶段态约束自动激活/休眠                 │
   137|└─────────────────────────────────────────────────────┘
   138|```
   139|
   140|结构化指令的本质 = 将连续强度约束基元统一提升至 S=1，并显式化其域和意图。

   144|## 2. 核心机制
   145|
   146|### 2.1 "噪音即出口"原理
   147|
   148|> **每一条不直接参与边界切割的信息，都是一个新的语义出口。**
   149|
   150|```
   151|"请总结这篇文章，尽量简洁，适当保留细节"
   152|
   153|  约束1: 总结          → 边界清晰
   154|  约束2: 尽量简洁      → 边界模糊（"尽量"=可做可不做）→ E+1
   155|  约束3: 适当保留细节  → 边界模糊（"适当"=可多可少）→ E+1
   156|
   157|  出口数 E(I) ≥ 2×2 = 4
   158|
   159|对比：
   160|
   161|"用不超过3句话总结文章的核心论点。不保留任何细节。"
   162|
   163|  每条约束边界清晰
   164|  出口数 E(I) = 1
   165|```
   166|
   167|### 2.2 注意力机制视角
   168|
   169|```
   170|冗长指令（1600 tokens）：
   171|  [约束A] [解释A] [例外A] [建议A] [约束B] [解释B] ...
   172|  → 约束A的注意力被解释稀释60%
   173|  → 约束B几乎被淹没
   174|  → 模型退回到预训练先验 → 多出口，随机选
   175|
   176|压缩指令（100 tokens）：
   177|  [约束A] [约束B] [约束C] [约束D]
   178|  → 每个token都是约束，零冗余
   179|  → 预训练先验被约束拓扑完全压制
   180|  → 唯一出口，确定性执行
   181|```
   182|
   183|### 2.3 必要冗余的功能（v2.0修正）
   184|
   185|去噪不应绝对化。冗余承担三项功能：
   186|
   187|```
   188|  ① 纠错容错：多信道表达容忍输入变异（错别字、同义词）
   189|  ② 隐含语境锚定：看似多余的背景帮助激活正确语义框架
   190|  ③ 关系线索维护：指代消解、限定条件嵌入在"冗余"短语中
   191|
   192|  结论：压缩=去噪是方向，但存在临界失真阈值
   193|       越过阈值→断崖崩溃，不是渐进下降
   194|       需要保真度度量来控制压缩截止点
   195|```

   199|## 3. 拓扑类型分类
   200|
   201|```
   202|                     约束的"硬度"
   203|              弱 ←────────────────→ 强
   204|       ┌─────────┬─────────┬─────────┬─────────┐
   205|       │  开放   │  穿孔   │  连通   │  封闭   │
   206|连通性 │ 拓扑    │  拓扑   │  拓扑   │  拓扑   │
   207|       │ (Open)  │(Punctrd)│(Conntd) │(Closed) │
   208|       ├─────────┼─────────┼─────────┼─────────┤
   209|强 ↑   │         │ 选择性  │ 理想    │ 完美    │
   210|  │   │         │ 逃逸    │ 约束    │ 模板    │
   211|  │   ├─────────┼─────────┼─────────┼─────────┤
   212|  │   │ 自然    │ 有漏洞  │         │ 过度    │
   213|弱 ↓  │ 语言    │ 的规则  │    X    │ 僵硬    │
   214|       └─────────┴─────────┴─────────┴─────────┘
   215|```
   216|
   217|- **开放拓扑**：自然语言，E≈∞，适用创意/头脑风暴
   218|- **封闭拓扑**：严格模板，E=1，适用流水线/结构化输出
   219|- **穿孔拓扑**：主体封闭+受控逃逸口，E=2-3，**工程最常用**
   220|- **连通拓扑**：所有约束互相强化指向同一出口，E=1，理想状态
   221|- **不连通拓扑**：约束矛盾，S_valid被切割成多个不连通区域，**反模式**。Agent不会崩溃，而是退回架构惯性（训练数据默认行为），在矛盾中寻找"最大公约数"→输出平庸/泛化的安全区内容
   222|
   223|### 动态拓扑切换（v2.0新增）
   224|
   225|拓扑不是静态的，应根据任务阶段自动切换：
   226|
   227|```
   228|  探索期 → 穿孔/开放拓扑（高弹性，允许多路径）
   229|       ↓ 收敛信号出现
   230|  收敛期 → 封闭/连通拓扑（出口收缩）
   231|       ↓ 确定性>阈值
   232|  执行期 → 单出口拓扑（低弹性，近乎刚性）
   233|       ↓ 风险触发
   234|  异常期 → 开放拓扑+安全出口（紧急泄压）
   235|```
   236|
   237|### 过渡拓扑（v2.1新增，解墨家攻击②）
   238|
   239|动态切换期间存在"切换窗口"，新旧出口可能同时有效，形成双出口。引入**过渡拓扑**解决：
   240|
   241|```
   242|  切换窗口问题：
   243|  状态A ──切换──→ 状态B
   244|    │出口A          │出口B
   245|    │    ┌────┐     │
   246|    └───→│冲突│←────┘
   247|         └────┘
   248|  切换窗口内双出口并存，破坏单出口原则
   249|
   250|  过渡拓扑解法：
   251|  切换时先冻结旧出口 → 进入"过渡态"（无出口/暂停执行）
   252|  → 确认新拓扑生效 → 激活新出口
   253|  → 过渡态期间如有紧急请求 → 走安全出口
   254|
   255|  时间线：
   256|  ─────┤冻结├────┤过渡态├────┤激活├─────
   257|       旧出口     无出口      新出口
   258|                  紧急→安全出口
   259|```

   263|## 4. 设计原则
   264|
   265|### 4.1 去噪原则（弹性化，v2.0修正）
   266|
   267|删除指令中所有不参与边界切割的内容，但保留必要冗余。
   268|
   269|```
   270|  弹性去噪：
   271|  高安全场景：r=0.1（近乎刚性匹配）
   272|  探索性场景：r=0.4（允许语义近似）
   273|
   274|  审查清单：
   275|  ☐ 删除这句话后，合法输出的集合会变大吗？
   276|    → 不会 → 噪声，删除
   277|    → 会   → 约束，保留
   278|  ☐ 删除后，保真度B是否下降？
   279|    → 下降 → 必要冗余，保留
   280|    → 不变 → 确认冗余，删除
   281|```
   282|
   283|### 4.2 单出口原则
   284|
   285|在给定上下文的任何状态下，指令应指向唯一的合法动作。
   286|
   287|```
   288|  反例："如果用户不满意，你可以道歉或提供替代方案"
   289|       → 两个合法动作，模型需要"判断"
   290|  正例："如果用户不满意：第一步道歉，第二步提供替代方案"
   291|       → 序列化，唯一出口
   292|
   293|  例外：开放拓扑场景（创意/头脑风暴）允许多出口
   294|       但需明确声明"这是设计意图，不是约束缺陷"
   295|```
   296|
   297|### 4.3 正交原则（放松至最小相关性，v2.0修正）
   298|
   299|每个约束应控制独立的维度。允许不可避免的耦合存在，用帕累托前沿找折中。
   300|
   301|```
   302|  坏的（重叠）：             好的（正交）：
   303|  "使用正式语气"             "输出JSON格式"      ← 结构维度
   304|  "不要使用俚语"             "每条不超过50字"    ← 长度维度
   305|  "保持专业"                 "仅用已提供参数"    ← 内容来源维度
   306|
   307|  不可避免的耦合（允许）：
   308|  "安全" ↔ "效率" → 用帕累托前沿找折中点
   309|```
   310|
   311|### 4.4 最小充分原则
   312|
   313|使用恰好足够的约束来完成任务，不多也不少。
   314|
   315|```
   316|  成功率
   317|    ↑      ╱‾‾‾‾‾‾‾‾╲
   318|    │    ╱              ╲
   319|    │  ╱    最优区间      ╲
   320|    │╱                      ╲______
   321|    └──────────────────────────────→ 约束数量
   322|    ↑              ↑              ↑
   323|  约束不足       最小充分       过约束
   324|  (E>1)        (E=1, 最优)    (模型忽略部分)
   325|
   326|  实践：3-7条正交约束通常足够
   327|```
   328|
   329|### 4.5 去噪 vs 冗余 裁决规则（v2.1新增，解墨家攻击④）
   330|
   331|去噪原则（删!）与必要冗余修正（留够!）存在矛盾。裁决规则：
   332|
   333|```
   334|  裁决流程：
   335|  对每条候选删除项执行消融测试：
   336|
   337|  删后性能显著下降 → 必要冗余，保留
   338|  删后性能不变     → 确认冗余，删除
   339|  删后性能略有下降 → 边界情况，看场景：
   340|    高安全场景 → 保留（宁可冗余不可脆弱）
   341|    低安全场景 → 删除（追求简洁）
   342|
   343|  优先级裁决：
   344|  H<0.3（可执行熵低，系统已高度确定）→ 最小充分优先
   345|  H≥0.3（系统仍有不确定性）→ 必要冗余优先（保鲁棒性）
   346|
   347|  原则：弹性让步于刚性的资源阈值
   348|```

   352|## 5. 度量方法（v2.0重构）
   353|
   354|### 5.1 质量三元组 (E, CR, B)
   355|
   356|```
   357|  出口计数 E：
   358|    E = 1      → 封闭拓扑，优秀
   359|    E ∈ [2,3]  → 穿孔拓扑，可接受
   360|    E ∈ [4,10] → 弱约束，需优化
   361|    E > 10     → 开放拓扑，不可控
   362|
   363|  压缩比 CR：
   364|    CR = (原始Token数 - 压缩后Token数) / 原始Token数
   365|    目标：CR > 0.8 且 成功率 = 100%
   366|
   367|  信息保真度 B（v2.0新增）：
   368|    B = 1 − δ·(1−1/CR)
   369|    δ = 被压缩遗漏的关键信息比例
   370|    目标：B > 0.95
   371|```
   372|
   373|### 5.2 可执行熵 H（v2.0新增）
   374|
   375|```
   376|  H = -Σ p(s) log p(s)  （根据基元强度加权）
   377|  理想结构化指令 → H → 0（唯一解）
   378|  自然语言多路径 → H 较高
   379|  过约束无解 → H 未定义 → 触发松弛回退
   380|```
   381|
   382|### 5.3 压缩-保真前沿（v2.0新增）
   383|
   384|```
   385|  IF (保真度)
   386|  1.0 ┤ * 原完整指令
   387|      │   \
   388|  0.9 ┤     * 可行压缩
   389|      │       \
   390|  0.7 ┤         *   ← 需找到这个前沿
   391|      │           \
   392|  0.5 ┤             *
   393|      └─────────────────────→ CR
   394|        1      2      3      4
   395|
   396|  必须联合度量，规定 IF_min 安全线
   397|  在保真度≥0.95的前提下最大化CR
   398|```
   399|
   400|### 5.4 分层适用性声明（v2.1新增，解R4）
   401|
   402|约束拓扑方法论与统一惯性理论在度量方向上存在张力：
   403|
   404|```
   405|  统一惯性理论：抵抗变化（惯性质量大=系统稳定）
   406|  约束拓扑：鼓励变化（可执行熵H低=约束精确）
   407|
   408|  表面矛盾：同一系统不能同时"最大化惯性"和"最小化熵"
   409|
   410|  分层解法：
   411|  约束拓扑工作在"适配层"——惯性可忽略的指令设计层
   412|  统一惯性理论工作在"行为层"——Agent实际执行时的惯性
   413|
   414|  ┌─────────────────────────────────────┐
   415|  │  适配层（指令设计）                  │
   416|  │  约束拓扑生效                       │
   417|  │  目标：E=1，H→0                    │
   418|  │  惯性：可忽略（指令是静态文本）      │
   419|  ├─────────────────────────────────────┤
   420|  │  行为层（Agent执行）                │
   421|  │  惯性理论生效                       │
   422|  │  目标：顺势诱导，利用惯性           │
   423|  │  约束拓扑：已内化为Agent的执行轨道  │
   424|  └─────────────────────────────────────┘
   425|
   426|  关系：约束拓扑设计指令 → 惯性理论指导执行
   427|       两层不冲突，各管各的
   428|```

   442|### 6.2 约束冲突
   443|
   444|```
   445|  直接矛盾："详细解释，但保持简短"
   446|  隐含矛盾："用专业术语，确保任何人都能理解"
   447|  资源矛盾："分析所有文件，在1秒内完成"
   448|
   449|  机制：Agent遇到矛盾时不会崩溃，而是退回架构惯性（训练数据默认行为），
   450|  在矛盾中寻找"最大公约数"→输出平庸/泛化的安全区内容。
   451|
   452|  "最大公约数"的规律：
   453|  详细↔简洁 → 退回"做个中等长度的摘要"
   454|  分析↔执行 → 退回"先分析一下然后给个建议"
   455|  创新↔保守 → 退回"给几个选项让用户选"
   456|  批判↔支持 → 退回"先说优点再说缺点"
   457|
   458|  隐含矛盾比直接矛盾更危险——两条约束单独看都合理，组合在一起互斥。
   459|
   460|  修复：去掉一个 / 优先级化 / 序列化
   461|```
